# 6 A judged recommendation at Gate 2

## Outcome
I want the verdict seat to propose what to do with each open finding and say why, with code
validating each proposal against the five Gate 2 verbs and overruling the illegal ones, so that
option A is a recommendation I can type as printed instead of a list of severities I still have
to weigh myself.

## Acceptance criteria
- AC-1 (behavioral): Given a verdict JSON whose open finding carries the seat's `action` and `why`, When `render_verdict.py` builds option A, Then that finding's line is the Gate 2 line for that action — `child from F#`, `home F# to <id>` or `waive F#: <the seat's why>` — and the `why` text appears in the line as the seat wrote it.
- AC-2 (critical): Given an open finding with `severity: block` and `action: waive`, When the rail validates the verdict, Then the proposal is refused, the action from `recommendations()` is used in its place, and the stored verdict JSON records the refusal with the finding id and the reason it was refused.
- AC-3 (behavioral): Given a proposal naming a verb outside the five, or a `home` target that is not an open ticket, or a `child` on a ticket other than this one, Then the same refusal path runs and `recommendations()` supplies that finding's action.
- AC-4 (property): For all verdicts, every open finding in option A has exactly one typable line, and every line option A prints is one of the five Gate 2 verbs — a test asserts it over the archived verdicts in `traces/verdict/`.
- AC-5 (behavioral): Given at least one refused proposal, Then the result block carries one line naming how many were refused and pointing at the page, and the page's "Recommended action" section names each refused finding and why; Given none were refused, Then the block carries no such line.
- AC-6 (behavioral): Given a verdict whose findings carry no `action` — every verdict written before this plan — Then option A is built from `recommendations()` exactly as today and the block says nothing about refusals.
- AC-7 (behavioral): Given any verdict, Then option A opens with one stance line whose verb is derived from `decision` and whose sentence is the seat's own, and no combination of verdict fields can make that verb and `decision` disagree.
- AC-8 (behavioral): Given two or more open findings whose files an earlier ticket's verdict already flagged, Then option A prints one collapsed line naming every id in the group and the earliest sighting, recommends `waive` for the group, and prints one `waive F#: <why>` line per id.
- AC-9 (critical): Given a finding an earlier ticket's verdict already flagged, Then no code path turns it into a child ticket on that fact alone, and a test asserts that eleven duplicate warns yield eleven `waive` lines and no `child from` line.
- AC-10 (behavioral): Given `skills/verdict/verdict-prompt.md` after the rewrite, Then it states what a complete recommendation contains, names what the rail refuses, enumerates no per-severity routing branch, and carries no instruction that needs a tool call or a second turn to follow.
- AC-11 (property): For all archived packets under `traces/verdict/`, `verdict_eval.py` scores the rewritten prompt and the previous one over the same packets and prints `decision_agreement` for both, and the run makes no network call beyond the verdict command itself.
- AC-12 (behavioral): Given `README.md` and `docs/architecture.md`, Then each says the Gate 2 recommendation is proposed by the seat and validated by code, and names the one non-negotiable: a block is never waived by a proposal.
- AC-13 (human): Given one real ticket at Gate 2 after this plan ships, a person confirms option A was typable exactly as printed and told them something the severity list did not.

## Out of scope
- Gate 2 itself. The five verbs, the `kanban_ops.py` calls, the board refusals and the human's
  authority are untouched; only what option A prints changes.
- A sixth verb. No group waive, no "waive all", no new board action — a group is still one typed
  line per id.
- A second model call. The proposal rides in the verdict call the seat already makes.
- The seat's findings themselves: severity, impact, consequence, `held`, `spawn_child` and `home`
  keep their meaning. This plan adds what to *do* about a finding, not how to judge one.
- `decision` semantics. `reject` iff an open block or CI red, as today; the stance reports it and
  never competes with it.
- The Gate 2 page's layout beyond the "Recommended action" section and the refusal detail in it.
- Seeding `traces/golden/`. The verdict seat's replay is `verdict_eval.py` over archived packets;
  the golden set belongs to the grill and stays out of this plan.
- Progressive disclosure by file routing for the verdict prompt. It is impossible here, see
  technical decision 5 — the prompt shortens by deleting, not by pointing.

## Modules
- `skills/verdict/verdict-prompt.md` — rewritten: what a complete recommendation is, what the rail refuses, no routing branches.
- `scripts/schemas.py` — the proposal's fields on the finding, the stance, and the refusal record, with `problems()` extended.
- `scripts/verdict_checks.py` — the rail: refuse an illegal proposal, fall back to the computed action, record the refusal.
- `scripts/render_verdict.py` — option A from the proposals, the typable `waive` line, the collapsed duplicate group, the refusal line.
- `README.md`, `docs/architecture.md` — who proposes, who validates, what is never waived.
