# 5 A small brief becomes one ticket, one gate, one verdict

## Outcome
I want a brief that names only ordinary paths to become one ticket with no plan page and no
Gate 1, so that small work costs one human touch and still leaves a packet, a verdict and a
Gate 2 behind, while work that turns out big is stopped at the diff budget and sent to the
full lane.

## Acceptance criteria
- AC-1 (behavioral): Given a brief whose named paths no charter `Applies to:` glob and no interface glob reach, which names no package, URL or env var and carries no partner-facing flag, When `triage.py <brief>` runs, Then it prints `light` with the four checks and their results and exits 0; Given any one check is true, Then it prints `full` and names the check that fired; Given a brief that names no path at all, Then it prints `full`.
- AC-2 (property): For all briefs, two runs of `triage.py` over the same brief, charter and interface globs print the same route, and the run makes no model call and no network call — a test asserts the route is a pure function of those three inputs.
- AC-3 (behavioral): Given a brief that triages `light`, When `/gates:grill <n>` runs, Then no `kanban/plans/<n>.plan.md` is written, exactly one ticket `kanban/tickets/<n>.1.<slug>.md` exists carrying `lane: light`, `parent: <n>`, a `writes:` list of the paths the brief named and `## Acceptance criteria` holding `- AC-<n>` lines written from the brief's "What I want" in one tool-less, one-turn call, and the session's last line is `Next: /gates:runner <n>.1`.
- AC-4 (behavioral): Given a brief that triages `full`, When `/gates:grill <n>` runs, Then the grill runs as today — tree, questions, plan page, Gate 1 — and every ticket it writes carries `lane: full`.
- AC-5 (critical): Given any lane, When a ticket is created, Then it is created through `kanban_ops.py new <n> <slug> --body-file <path>`, which writes `kanban/tickets/<n>.<m>.<slug>.md` when `kanban/.issues` is absent and creates the issue when it is present; no other code path writes a ticket file.
- AC-6 (behavioral): Given a ticket carrying `lane: light`, When the runner's `feat-commit` phase is done, Then the runner counts insertions plus deletions against the base branch over the ticket's `writes:` scope and the included paths, and at or under 150 continues to `ci` exactly as today.
- AC-7 (behavioral): Given that count is over 150, Then the runner writes `done error light over budget` naming the count and the budget, deletes the `ticket/<id>` branch, sets the ticket `superseded` with a Log entry naming `/gates:grill <n>`, calls no verdict seat, exits 2, and starts no grill of its own.
- AC-8 (behavioral): Given a light ticket reaches Gate 2, Then `traces/verdict/<id>.{input.md,json,summary.json,html}` are written as for any ticket, the session prints `traces/runs/<id>.result` and nothing else, and the same five Gate 2 words run the same `kanban_ops.py` calls.
- AC-9 (behavioral): Given a light ticket ends, by ship or over budget, Then one JSON line is appended to `traces/lanes.jsonl` carrying the ticket id, the lane, the seconds from the brief's first commit to that end, the human touches counted, the changed-line count and whether the budget fired; the record loads through a schema in `scripts/schemas.py` and no board or page renders it.
- AC-10 (behavioral): Given `README.md` and `docs/architecture.md`, Then each names the light lane, its four triage checks and the 150-line budget.
- AC-11 (human): Given one real small brief run end to end, a person confirms they typed one command before Gate 2 and that the result block was all they needed to ship.

## Out of scope
- A model call inside triage. The route stays a pure function; a miss on check 2 is left to the verdict.
- "Needs more than one ticket" as a triage check. The budget catches it after the build.
- Any change to the full lane: its tree, questions, plan page, Gate 1 and routing stamp are untouched.
- `hooks/guard_writes.py`: unchanged; a light ticket's `writes:` is already what rule 3 reads.
- A light flag in `render_verdict.py`: the Gate 2 page is written as today, for the record.
- A board surface, a page or a stats command for the lane record.
- Auto-shipping a light ticket. Gate 2 stays a human decision.
- Starting the grill from the runner when the budget fires. The runner stops and names the command.

## Modules
- `scripts/triage.py` — the four checks over a brief, the route and its reasons, zero tokens.
- `scripts/schemas.py` — `Triage` and the lane record; the interface glob file parsed like the charter's `Applies to:` lines.
- `scripts/kanban_ops.py` — `new` writes the ticket file when `kanban/.issues` is absent.
- `skills/grill/SKILL.md` — triage first, a light brief short-circuits to one ticket.
- `scripts/runner.py` — the budget count after `feat-commit`, the over-budget stop, the lane record.
- `docs/domain-pack/interfaces.md` — the interface and schema globs check 2 reads.
