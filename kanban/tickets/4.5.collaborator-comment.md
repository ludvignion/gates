# 4.5 A collaborator's comment reaches the next session

## Outcome
A comment left on the issue is in the mirror's `## Log` before the next build session reads the ticket, without anyone copying it.

## Acceptance criteria
- AC-1 (behavioral): Given the marker and a new issue comment, When a session starts (`SessionStart` startup hook) or `/gates:build <id>` begins, Then the sync runs before the ticket is read and the comment is in the mirror's `## Log`; the build skill names the step and a test pins it (plan 4 AC-10)
- AC-2 (behavioral): Given no marker, When a session starts, Then the startup hook exits 0 at once with no `gh` call (plan 4 AC-0)
- AC-3 (human): Given the repo's Issues tab, a person confirms the tickets show status labels, opens one, reads it as a ticket, and leaves a comment (plan 4 AC-15)
- AC-4 (human): Given a `ready` issue, a person confirms they can pick it up by creating `ticket/<number>` and the next build session shows their comment in the Log (plan 4 AC-16)

## Out of scope
- notifying anyone of comments
- flipping a label on branch creation
