# 6.3 Repeat findings collapse to one waived line

## Outcome
Findings whose files an earlier ticket's verdict already flagged collapse into one line naming
every id and the earliest sighting, recommended for waiving, and nothing turns a second sighting
into a child ticket any more.

## Acceptance criteria
- AC-1 (behavioral): Given two or more open findings whose files an earlier ticket's verdict already flagged, Then option A prints one collapsed line naming every id in the group and the earliest sighting, recommends `waive` for the group, and prints one `waive F#: <why>` line per id (plan 6 AC-8).
- AC-2 (critical): Given a finding an earlier ticket's verdict already flagged, Then no code path turns it into a child ticket on that fact alone, and a test asserts that eleven duplicate warns yield eleven `waive` lines and no `child from` line (plan 6 AC-9).
- AC-3 (property): For all verdicts, the earlier-sighting lookup runs once per group rather than once per finding, and a test asserts the number of `traces/verdict/` reads does not grow with the group's size.
- AC-4 (behavioral): Given a group whose repeats come from three different earlier tickets, Then the collapsed line names the earliest sighting and the count of the others, and stays one line.

## Out of scope
- The `Second sighting:` line inside a single finding's block, which keeps its present shape.
- Any new verb for waiving a group in one command.
- Changing what counts as the same finding beyond the file-name match `seen_before` already makes.
