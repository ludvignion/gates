# 4.4 Lint on GitHub history, CI template, Dockerfile, .env.example

## Outcome
In an opted-in project `make kanban` reports a closed issue edited after closing or reopened; CI syncs before it with `issues: read`; the runner image has `gh`; `.env.example` names `GH_TOKEN`.

## Acceptance criteria
- AC-1 (behavioral): Given the marker and a closed issue whose body was edited after `closedAt` or with a `reopened` timeline event, When `lint_kanban.py` runs with GitHub access, Then it reports the number and what changed; without access it prints that the rule was not checked; without the marker rule 1 runs on git as today (plan 4 AC-12) (plan 4 AC-0)
- AC-2 (behavioral): Given a mirrored ticket whose source body carries a `status:` line, When `lint_kanban.py` runs, Then it fails naming the issue (plan 4 AC-2)
- AC-3 (behavioral): Given the template CI workflow, Then it runs the sync before `make kanban` and declares `permissions: issues: read`; Given `.env.example`, Then it names `GH_TOKEN` with its scope; Given `Dockerfile`, Then it installs `gh` (plan 4 AC-13)

## Out of scope
- a GitHub Action of any kind
- building the Docker image in tests
