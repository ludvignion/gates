# 5.3 Every light ticket leaves one measured line behind

## Outcome
A light ticket that ends, by ship or over budget, appends one schema-backed JSON line to `traces/lanes.jsonl`, and the repo's docs name the lane, its checks and its budget.

## Acceptance criteria
- AC-1 (behavioral): Given a light ticket ends, by ship or over budget, Then one JSON line is appended to `traces/lanes.jsonl` carrying the ticket id, the lane, the seconds from the brief's first commit to that end, the human touches counted, the changed-line count and whether the budget fired; the record loads through a schema in `scripts/schemas.py` and no board or page renders it (plan 5 AC-9)
- AC-2 (property): For all records written, the file stays append-only and a malformed or missing `traces/lanes.jsonl` never fails a run: the runner logs the failure and carries on (plan 5 AC-9)
- AC-3 (behavioral): Given `README.md` and `docs/architecture.md`, Then each names the light lane, its four triage checks and the 150-line budget (plan 5 AC-10)
- AC-4 (human): Given one real small brief run end to end, a person confirms they typed one command before Gate 2 and that the result block was all they needed to ship (plan 5 AC-11)

## Out of scope
- A board row, a page or a stats command for the lane record
- Comparing the record against the last plan's tickets in code; the human reads the file
- Triage, the light ticket and the budget stop — 5.1, 5.2
