# 4.6 `init --issues`: preflight, labels, migration of file tickets, first sync

## Outcome
A project opts in with one command that checks `gh`, writes the marker, creates labels, migrates every file ticket to an issue, rewrites the plans and syncs once; or refuses and writes nothing.

## Acceptance criteria
- AC-1 (behavioral): Given `init --issues <owner/repo>`, When `gh auth status` succeeds and the repo has issues enabled, Then `kanban/.issues` is written, the labels exist, `kanban/tickets/` is git-ignored and `make sync` has run; otherwise it refuses naming what is missing and writes nothing (plan 4 AC-13)
- AC-2 (behavioral): Given file tickets under `kanban/tickets/`, When `init --issues` runs, Then one issue per file is created with the same body shape, `done` and `superseded` ones created closed, each Log entry one comment in order, the plans' `## Slices` cite the new numbers, and the files are deleted in one commit listing old id → new number (plan 4 AC-14)
- AC-3 (behavioral): Given `init --update` on an opted-in project, Then the template's Makefile `sync`, CI and `.env.example` changes land and the marker is kept
- AC-4 (behavioral): Given README and CHANGELOG, Then they describe opt-in, the marker, `make sync`, and the migration

## Out of scope
- opting out
- migrating verdict traces
